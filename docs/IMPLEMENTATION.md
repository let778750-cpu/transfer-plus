# 0.3.0 实现说明

用户入口保持为 PDF 工具栏“翻译”。`main.ts` 负责任务与原附件映射；`service.ts` 仅访问带随机令牌的回环服务。设置第一栏是 AI Studio 访问令牌，翻译凭据单独保留。两种密钥只由服务以 DPAPI 保存，返回配置只含是否已配置的标志。

## 流程与边界

1. `service.py` 依原文 SHA256、处理配置及规则版本查存档；旧规则必须重新建立识别清单。
2. `paddle_cloud.py` 使用官方异步任务接口。原文件按 20 页/40 MB 分批，先持久化批次身份再上传；任务编号立即保存。取消后查询已有任务；连接建立失败可重试，响应不明先查询批次，过期任务释放编号后重试。结果页数与页索引必须完整。
3. `cloud_layout.py` 将原 PDF 字符与云端布局对齐；PP-StructureV3 单元格只能接收完整原文行，不完整单元格清单不能丢弃未分配文字；图表与扫描文字另调用 PP-OCRv6。
4. `cloud_pipeline.py` 维护统一内容清单，复用有效段落译文，从原文重新排版。普通斜体不是类别跳过条件；简单数学复制原字形，复杂数学固定原位并翻译周围自然语言。复杂公式拆分后仍留在清单作为不可覆盖区域。
5. `reading.py` 和 `direct_pdf.py` 实施局部排版与字形检查；目的区域扩展不扩大可删除源字符集合。不能可靠分离的图中文字、扫描公式和排版失败区域明确未完成。
6. `attachment_update.py` 在用户现有附件文件旁完成原子更新前的备份准备；批注锚点变体不修改共享存档。服务签发交付编号，`imported` 校验实际交付哈希及附件身份，再保存对应报告。

两篇工作任务可并发网络处理，`typesetting.lock` 令本机 PDF 合成串行。远端没有已公开的取消接口；取消只阻止本机后续请求与交付，完整识别和翻译存档可恢复。

## 存档层次

- OCR：文件字节哈希、模型、解析参数、传输结构版本。
- 内容清单：原文哈希、模型、选择页、布局规则版本。
- 段落译文：源文本、模型、目标语言、术语、提示规则。
- 最终 PDF：原文哈希、完整处理配置、原始清单指纹、结果哈希。

无缺项的当前存档只做本机检查。旧存档迁移保留已校验译文，但不能复用旧的类别排除结果。当前界面不挂载补译或参考文本面板。

## 当前验收边界

真实 API 的坐标字段、模型可用性、云端额度及复杂实际论文效果等待用户填写 AI Studio 令牌后验证。本轮离线测试不能替代这些验收。只进行选定论文的一页结构验证，再检查用户指出的区域和完整交付，不遍历翻译整个文库。详见 ACCEPTANCE.md。
